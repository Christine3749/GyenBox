# GY 输入法中心 VI 标准

版本：1.0
状态：项目基准
适用范围：`shurufa.gyenbox.com` 的词库工作台、个人学习与输入法配置界面

## 1. 设计定位

GY 输入法中心是一个面向词库管理与输入效率的工作台，不是安全控制台，也不是营销首页。

产品层级固定为：

1. **词库核心**：公共词库、个人词库、搜索、词频、固定词、导入导出与同步。
2. **个人学习**：用户确认过的词、词频分层、收藏、Keep 卡片与跨设备同步。
3. **配置辅助**：输入法外观、候选数量、按键行为、英文直通、隐私与设备配置。

界面必须让用户一眼看见词库能力。个人配置可以进入侧栏，但不得压过词库工作台。

## 2. 视觉性格

- 原版 ciku 的深色数据工作台为第一视觉来源。
- 信息密度适中，重视表格、状态、数量和可追溯操作。
- 蓝色承担主要操作和选中状态；绿色、橙色只表达状态等级，不作为装饰。
- 组件保持紧凑、直角偏圆的工程感；不使用大面积渐变、玻璃效果或紫色安全控制台风格。
- “借鉴 SafeAuth”仅指借鉴状态可见性、间距一致性、焦点可访问性等方法，不复制 SafeAuth 的颜色、语气或页面结构。

## 3. 色彩令牌

| 用途 | 色值 | 规则 |
| --- | --- | --- |
| 页面底色 | `#050608` | 全局工作区背景 |
| 顶栏 / 侧栏 | `#0d0e12` | 导航容器，不使用纯黑 |
| 卡片 | `#11131c` | 指标、表格、设置卡片 |
| 内层表面 | `#161824` | 标签、输入框、次级操作 |
| 边框 | `#222532` | 一级分隔线 |
| 边框强调 | `#272a38` | 控件边框、标签边框 |
| 标题 | `#f4f4f5` | 页面标题与关键词 |
| 正文 | `#cbd5e1` | 常规数据文本 |
| 次要文字 | `#a1a1aa` | 说明、表头、辅助信息 |
| 弱化文字 | `#71717a` | 不抢夺注意力的元数据 |
| 主操作蓝 | `#2563eb` | 主按钮、选中项、焦点 |
| 蓝色悬停 | `#3b82f6` | 主操作悬停与高亮 |

| 高频 / 警示 | `#f97316` | 高频词、需要注意的状态 |

不得为了“统一”而用全局 CSS 强制覆盖已有组件的圆角、颜色、阴影或渐变。组件应在自身 class 中明确表达语义。

浅色模式使用同一套尺寸、层级和语义色，仅切换表面与文字令牌：

| 用途 | 浅色值 |
| --- | --- |
| 页面底色 | `#f5f7fb` |
| 导航底色 | `#ffffff` |
| 卡片表面 | `#ffffff` |
| 内层表面 | `#f8fafc` |
| 边框 | `#dbe2ea` |
| 标题 | `#0f172a` |
| 正文 | `#334155` |
| 次要文字 | `#475569` |
| 弱化文字 | `#64748b` |

浅色不是简单的“白底开关”：首页、表格、个人中心、输入法设置、弹窗和空状态都必须完成表面、边框和文字的成套切换。

## 4. 尺寸与排版

- 使用 4px 基准网格；常用间距为 `8 / 12 / 16 / 24px`。
- 页面卡片间距通常为 `12px`，主页面内边距为 `16px`，宽屏可扩展至 `24px`。
- 工作台卡片使用约 `6px` 圆角；按钮和输入框使用 `4–6px` 圆角。
- 只在同步状态、词频等级、来源词库等短标签上使用胶囊或小圆角。
- 中文正文使用系统无衬线字体；拼音、Revision、数量、版本和域名使用等宽字体。
- 标题清楚分级，表格列标题小而稳定，不能用过大的展示字体挤压数据区域。

## 5. 组件与交互

### 导航

- 顶栏展示 `GY`、`词库工作台` 和当前统一入口 `shurufa.gyenbox.com`。
- 侧栏首先展示词库概览、全局搜索和词库分类；输入法设置放在独立的辅助分组。
- 当前选中项必须同时有背景、边框或蓝色指示，不得只依靠颜色。

### 数据卡片与表格

- 指标卡只展示可行动的数字：公共词库、个人词条、待审核、高频与固定词。
- 词频分布使用“一次词 / 记忆词 / 高频词 / 固定词”四级语义，并保持颜色稳定。
- 表格优先显示词语、拼音、释义、使用次数、来源和等级；详情操作保持在行末。
- 私人词条与公共词条必须在来源和同步状态上明确区分。

### 输入法设置

- 设置页沿用 ciku 工作台的卡片、边框、蓝色和等宽标签，不另起一套紫色主题。
- 每个开关必须有标题和一句解释；涉及 Shift、英文直通、密码框、Tab 等行为时必须说明实际结果。
- 保存、恢复默认、同步等操作必须有明确反馈；不能静默改变用户配置。

### 状态与可访问性

- 正常、待处理、错误、离线状态必须有文字，不只使用绿/橙/红色。
- 键盘焦点使用蓝色 `2px` 外框并保留可见偏移。
- 可操作控件的有效高度不低于 `36px`；移动端主要操作尽量达到 `44px`。
- 减少动态效果；不使用持续闪烁或会干扰输入的动画。

## 6. 响应式规则

- 桌面端保持紧凑侧栏和宽表格。
- 窄屏侧栏改为抽屉；顶栏保留 GY 标识、搜索入口和主要操作。
- 表格允许横向滚动，不强行把拼音和释义压成不可读的窄列。
- 设置卡片在窄屏单列排列，操作按钮仍保持清晰的主次关系。

## 7. 明确禁止

- 不把 ciku 原版替换为 SafeAuth 的完整页面风格。
- 不引入大面积紫色、玻璃拟态、渐变光晕或“安全控制台”文案。
- 不用一个全局选择器批量改写所有组件的圆角、阴影和颜色。
- 不让个人配置成为首页主角；词库能力必须始终是第一层级。
- 不把一次输入自动写入公共词库；个人数据必须与公共词库隔离。

## 8. 工程落地规则

- 深色原版 ciku 是默认基准；新增页面先完成深色，再补齐浅色，不得用浅色改动反向破坏深色。
- 新增组件优先使用本标准的语义 class；遗留页面的 Tailwind 类只能做局部主题适配，不得再添加全局强制覆盖器。
- 主题适配至少覆盖：背景、卡片、内层表面、边框、标题、正文、辅助文字、焦点和状态标签。
- 主题切换必须可通过键盘完成，且焦点在切换前后保持可见。
- 每次视觉改动都要同时检查首页、个人中心、输入法设置和一个详情/弹窗页面。

## 9. 验收基准

一次 VI 验收至少检查：

- 首页是否首先呈现词库工作台与词频数据；
- 搜索、导入、新建、同步等核心操作是否可见且有反馈；
- 个人中心是否可以从辅助分组进入，且视觉上与原版 ciku 一致；
- 深色页面是否没有 SafeAuth 紫色覆盖；
- 颜色、间距、圆角、焦点状态和窄屏布局是否遵守本标准；
- 视觉改动是否是局部增强，而不是替换产品原有识别度。
- 深色和浅色是否分别截图验收，且浅色不再出现“白色外壳 + 深色内容”的混合状态；
- 个人中心、输入法设置与词库首页是否共享同一套尺寸、边框和状态语义。
