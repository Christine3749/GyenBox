# SafeAuth 深色标准 VI

> 状态：**深色视觉性格基准（Dark only）**  
> 适用范围：SafeAuth 的产品界面、原型、营销内嵌产品截图及后续新增组件。  
> 本文只定义深色模式。色彩 token、交互状态和可访问性以 [SafeAuth × Material 3 深色设计系统](./SAFEAUTH-M3-DARK-DESIGN-SYSTEM.md) 为实现标准；浅色模式使用单独的 [浅色设计系统](./SAFEAUTH-M3-LIGHT-DESIGN-SYSTEM.md)。本文定义其终端安全视觉性格。

## 1. 设计原则

- **终端安全感**：近黑底色、精细分区、等宽系统标签、低圆角；信息必须像可信的安全控制台，而不是消费级 SaaS。
- **颜色有语义**：紫色是系统主控色；青蓝、青绿、紫、琥珀、玫红只用于账号分类或风险状态。
- **克制的动效**：反馈应短促、可预测，不能弹跳、漂浮或出现装饰性的长动画。
- **优先紧凑列表**：账号页默认使用横向紧凑列表；网格是辅助视图而不是默认首页。

## 3. 字体与文本

- **主字体**：`font-mono`。所有品牌、服务名、验证码、标签、数字与系统性文字必须使用等宽字体。
- **说明文字**：仅完整句子的中文说明可以使用无衬线字体（`font-sans`），例如备份说明和 AI 审计摘要。
- **英文系统语法**：使用大写和下划线，例如 `OFFLINE_ZERO_KNOWLEDGE`、`[ BACKUP_ARCHIVE ]`、`VAULT_PROTECTED`。
- **字号层级**：
  - 微标签：8px / 9px / 10px；用于 `SCORE`、键盘提示、类别标签。
  - 元数据：11px；用于副标题、说明、状态串。
  - 正文与控件：12px。
  - 服务名：12px，窄屏可升至 14px。
  - 区块标题：18px（`text-lg`）。
  - 紧凑验证码：16px；展开验证码：24px，桌面可升至 30px。
- **字距**：系统标题与微标签 `tracking-wider` / `tracking-widest`；验证码必须 `tracking-widest`。正文不得过度加宽。

## 4. 几何、尺寸与布局

### 4.1 基础尺度

| 项目 | 标准 |
| --- | --- |
| 间距栅格 | 4px 基准；常用 4 / 6 / 8 / 12 / 14 / 16 / 20 / 24 / 32px |
| 圆角 | 默认 `2px`（`rounded-sm`）；微标签可 `1px`；禁止大圆角和药丸型按钮 |
| 普通边框 | 1px 实线 `border` |
| 选中导航左边 | 2px `accent`；隐藏区使用 2px Amber |
| 阴影 | 仅 `shadow-xs` / `shadow-sm`，用于区分层级；禁止柔和的大面积漂浮阴影 |
| 滚动条 | 宽/高 4px；轨道 `#0B0B0F`；滑块 `#272738`；悬停 `accent`；直角 |

### 4.2 页面骨架（桌面）

| 区域 | 标准 |

## 5. 组件状态与交互

### 5.1 全局状态

- 默认：`surface-2` 或 `surface-1` + 1px `border`。
- 悬停：表面升至 `surface-active` 或 `surface-hover`；边框可升至 `border-strong`。不改变圆角，不使用强光晕。
- 焦点：输入框使用 `accent` 1px 边框；保留浏览器可访问性焦点。
- 按下：主操作按钮可以 `scale(0.95)`；数字键改为 `accent` 边框和文字。
- 禁用：保留结构、降低内容对比度；不以透明大面积蒙版取代状态说明。

### 5.2 顶栏

- `/` 键在非输入状态时聚焦搜索框，并显示同一快捷键提示。
- 列表 / 网格切换是同一个 2px 圆角控件组；选中项使用 `accent` 实底和白字。
- 锁定、信息、主题图标都是次级操作，保持深色描边按钮；新增账号为唯一紫色主操作。
- 深色 VI 不定义浅色模式的视觉、文案或验收项；后续深色交付不得依赖浅色来表达状态。

### 5.3 导航与账号列表

- 当前分类：`surface-active`，左侧 2px 系统色，文字高亮，数量徽标为对应主色实底。
- 非当前分类：透明背景；悬停才显示 `surface-2`。
- 点击完整账号行展开验证码详情；不能要求用户精确点击标题或图标。
- 受保护账号先显示锁定状态，点击后进入 PIN 二次验证，不能直接泄露验证码。
- 复制成功后，按钮图标暂时切换为确认态并显示 Toast；验证码仍保持可读。
- TOTP 倒计时每秒刷新；剩余 5 秒或以内变为 Rose 临期状态。

### 5.4 HUD 与弹窗

- `hud-box` 使用右上/左下以外的对角短角标：6 × 6px，2px `accent` 描边，向容器外偏移 1px。
- 弹窗遮罩使用黑色 80%（深色）；弹窗本体使用 `#121218` 或同等深层表面、1px `border`、2px 圆角。
- 弹窗标题/工具区与内容区之间使用 1px 分隔线；高风险操作必须带明确动作文案，不用隐晦图标代替。

## 6. 动效与时间

| 场景 | 标准 |
| --- | --- |
| 通用颜色/表面过渡 | 150–200ms，`ease-out` 或默认平滑；只对实际变化的属性过渡 |
| 账号行展开 | 150ms；仅内边距、背景、内容淡入，不做位移动画 |
| 内容淡入 | 150ms，透明度 0→1，Y 轴 -2px→0 |
| PIN 错误抖动 | 300ms；X 轴 `0 → -6 → 6 → -3 → 0px` |
| 主按钮按下 | 即时 `scale(0.95)`，松开恢复 |
| TOTP 进度 | 1000ms 线性更新 |
| 复制确认 | 2000ms |
| Toast | 2500ms |
| PIN 错误清空 | 600ms；生物模拟解锁 400ms；PIN 重置成功 800ms |

## 7. 禁止项

- 不使用白色或浅灰色为页面背景；不引入浅色模式色板到本规范。
- 不使用超过 2px 的圆角作为默认；不使用胶囊式组件。
- 不使用渐变背景、大面积玻璃拟态、发光边框、3D 插画或彩色噪点。
- 不将类别色作为全页背景；不让多个高饱和颜色竞争主操作。
- 不使用大段非等宽英文系统文案；不把系统操作写成泛化的“提交”“确认”而失去安全语义。
- 不以“美化”为由弱化锁定、风险、倒计时、复制等关键安全状态。

## 8. 实现验收清单

- [ ] 新页面背景、层级、边框和按钮均使用第 2 节的深色令牌。
- [ ] 所有新增交互均有默认、悬停、焦点、按下、禁用/加载状态。
- [ ] 主操作每个区域最多一个紫色实底按钮。
- [ ] 标题、系统标签、验证码和技术元数据使用等宽字体。
- [ ] 默认账号列表为紧凑列表，展开与复制流程符合第 5 节。
- [ ] 动画时长和效果不超过第 6 节规定；支持 `prefers-reduced-motion` 时应停用非必要动画。
- [ ] 任何浅色视觉方案不作为本次验收对象。
